# Массовая сверка старого и нового сервисов

`compare_services.py` прогоняет набор входных записей через **оба** сервиса
(старый `.asmx` и новый `/ws`), сравнивает ответы и делает **один HTML-отчёт**:
список `nrec` (зелёный — совпало, красный — различие, серый — ошибка), галочка
«скрыть совпавшие», по клику на строку — полный ответ обеих функций и подсветка
различий.

Только стандартная библиотека Python 3 — на офлайн-ПК ничего ставить не нужно.

## 1. Подготовить вход (CSV)
Выгрузить результат SQL тестировщика в CSV с колонками **в этом порядке**:
```
nrec,date1,date2,type_org,code_org,fam,im,ot,w,dr,vpolis,npolis,doctype,docser,docnum,ss,mr
```
Строка-заголовок необязательна (если первая ячейка — `nrec`, она пропускается).
Даты можно в формате `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` — скрипт приводит `date1/date2/dr`
к нужному формату сам. Кодировка — UTF-8.

## 2. Запустить сверку
```
python3 scripts/compare_services.py \
    --input inputs.csv \
    --old-url http://<хост-старого>/IASWeb/InsCheckTest/InsCheck.asmx \
    --new-url http://<хост-нового>:8080/ws \
    --out report.html
```
Параметры: `--timeout` (сек, по умолчанию 30), `--workers` (параллельных запросов, 8).

## 3. Открыть отчёт
`report.html` — самодостаточный файл, открывается в браузере офлайн. Данные внутри,
интернет/сервер не нужны. По умолчанию совпавшие скрыты — видно только различия и ошибки.

## Заметки
- Скрипт шлёт обоим сервисам одинаковый SOAP-конверт (плоский `<query>`), с заголовком
  `SOAPAction`. Сравнение — по канонизированному `<answer>` (без учёта префикса namespace
  и форматирования), т.е. `ns2:` vs без префикса на результат сверки не влияет.
- Перед массовым прогоном лучше выключить DEBUG-лог нового сервиса
  (`logging.level.ru.iac.inscheck: INFO` в application.yml), иначе лог распухнет.
